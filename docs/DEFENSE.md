Сначала разберитесь, где лежат данные, затем проследите один клик по сердечку и одну отправку формы. После этого открывайте исходники: комментарии на русском отмечают основные шаги.

## Где хранятся данные

| Место | Назначение | После обновления страницы |
| --- | --- | --- |
| Vuex | Общая память работающего приложения: списки, ошибки, состояние запросов | Создаётся заново |
| localStorage | Строковое хранилище этого браузера: избранное и авторизация | Значения остаются, если браузер разрешил сохранение |
| MockAPI | Внешний учебный сервер: вакансии и отклики | Отклики можно снова получить через GET |

Vuex сам ничего навсегда не сохраняет. В избранном код отдельно записывает JSON в localStorage. Для откликов код отдельно делает POST на сервер. Отклики в localStorage не записываются.

## Один клик по сердечку

```text
Клик по FavoriteButton
  → $emit('toggle'): кнопка сообщает родителю о нажатии
  → JobCard или JobDetailPage вызывает toggleFavorite()
  → dispatch('favorites/toggleFavorite', job) запускает action
  → action готовит список и вызывает commit('SET_LIST', updatedJobs)
  → mutation заменяет state.list
  → Vue обновляет связанные computed и интерфейс
  → внутри action список также сохраняется в localStorage
```

**Props идут от родителя к ребёнку, событие — от ребёнка к родителю.** Родитель передаёт `:active="isFavorite"`: «Покажи текущее состояние». Ребёнок делает `$emit('toggle')`: «На меня нажали». Сама кнопка не знает, куда сохранять вакансию. Родитель знает объект `job` и передаёт его в Vuex.

| Часть Vuex | За что отвечает |
| --- | --- |
| `state` | Данные: список, флаги загрузки и ошибки |
| `getters` | Ответы, вычисленные из state: например, избранная ли вакансия с данным ID |
| `mutations` | Синхронное изменение state, вызывается через `commit` |
| `actions` | Последовательность действий: проверить, вызвать mutation, сохранить или дождаться API; вызывается через `dispatch` |

`namespaced: true` добавляет имя модуля к команде: `favorites/toggleFavorite`. `state()` возвращает начальные данные нового экземпляра store. Компонент читает состояние, а изменение проводит через action и mutation.

## favorites.js по шагам

1. `STORAGE_KEY` задаёт ключ `favorites` в браузере. `normalizedId` приводит ID к строке: число `1` и строка `'1'` считаются одной вакансией.
2. `isValidJob` через обычные `if` проверяет объект и ID. Разрешены непустая строка или конечное число.
3. `loadFavorites` читает строку через `getItem`, разбирает её `JSON.parse` и проверяет массив. Цикл `for...of` проверяет вакансии, `some` ищет уже добавленный ID, `push` добавляет только уникальные записи.
4. Если записи нет, возвращается пустой список без ошибки. Если JSON повреждён или чтение запрещено, `catch` возвращает пустой список с предупреждением; приложение продолжает работать.
5. Getter `isFavorite(state)` возвращает функцию с параметром `id`. Поэтому вызов выглядит так: `this.$store.getters['favorites/isFavorite'](job.id)`.
6. `toggleFavorite` проверяет вакансию. Если она уже сохранена, `filter` создаёт список без неё. Иначе `slice()` копирует список и `push({ ...job })` добавляет поверхностную копию вакансии. Затем вызываются `SET_LIST` и `saveFavorites`.
7. `saveFavorites` превращает массив в строку через `JSON.stringify` и записывает `setItem`. Если запись не удалась, список в Vuex остаётся, но появляется предупреждение: после F5 изменение может пропасть.
8. `removeFavorite` выполняет только удаление по ID и тоже сохраняет результат; сердечко использует переключение через `toggleFavorite`.

Избранное общее для аккаунтов в одном браузере на одном адресе сайта. Оно сохраняет снимок вакансии: при изменении серверной вакансии карточка в избранном может устареть.

## FavoriteButton.vue и FavoritesPage.vue

У кнопки два Boolean-prop: `active` и `disabled`, по умолчанию `false`. `emits: ['toggle']` объявляет исходящее событие. `@click.stop="$emit('toggle')"` отправляет это событие и останавливает всплытие DOM-клика. `type="button"` не даёт кнопке случайно отправить форму.

`:class` и `:fill` меняют вид сердечка по значению `active`. `:disabled` управляет доступностью кнопки, а `aria-pressed`, `aria-label` и `title` описывают действие и состояние. Компонент используется в карточке и на странице вакансии.

У страницы избранного `computed.favorites` и `computed.error` читают Vuex. Отдельная копия списка в `data` не нужна. `v-if` показывает предупреждение и пустое состояние, `v-else` — список `JobCard`. `v-for` создаёт карточки, `:job` передаёт объект, `:key="job.id"` помогает Vue различать записи.

Событие карточки `open` передаёт ID в `openJob`. Метод вызывает `$router.push` для `/jobs/:id`; `encodeURIComponent` подготавливает ID для URL. Удаление из общего store сразу отражается на этой странице.

## applications.js по шагам

Четыре небольшие функции подготавливают работу: `getCurrentUserId` получает ID из `auth`; `trimText` принимает строку и убирает пробелы по краям; `isCurrentSession` проверяет актуальность запроса; `errorMessage` превращает техническую ошибку в понятный текст.

Состояние модуля: `list` — отклики, `loading` — ожидание GET, `submitting` — ожидание POST, `error` — ошибка GET, `submitError` — ошибка проверки/POST. `sessionVersion` — номер сессии, увеличивается при `RESET`.

Getter `userApplications` отбирает записи с точным совпадением `userId` и сортирует новые первыми. `filter` уже создаёт новый массив, поэтому последующий `sort` не изменяет исходный `state.list`. `ADD_APPLICATION` убирает прежнюю запись с тем же ID и добавляет полученную в начало через `unshift`.

**Загрузка — `fetchApplications`:**

1. При уже выполняющемся GET второй не запускается. Без пользователя список очищается и появляется сообщение о необходимости входа.
2. Action запоминает пользователя и номер сессии, включает `loading`, убирает старую ошибку и старый список.
3. `await applicationsApi.get(resource, { params: { userId: userId } })` получает список. `params` становится частью URL после `?`.
4. Ответ проверяется как массив и точно фильтруется по владельцу. Результат записывается через mutation только для актуальной сессии.
5. `catch` записывает ошибку, `finally` выключает `loading` для той же сессии.

**Отправка — `submitApplication`:**

1. Action блокирует одновременный повторный POST, получает пользователя, убирает пробелы и повторяет проверку полей.
2. Создаёт `payload`, включает `submitting` и ждёт `applicationsApi.post(resource, payload)`.
3. Проверяет ответ: должен прийти объект с непустым `id`. Без такого подтверждения сохранение не объявляется успешным.
4. `Object.assign({}, saved, payload)` собирает новый объект из ответа и проверенных отправленных полей; затем сохраняется серверный `id`. Action вызывает `ADD_APPLICATION` для актуальной сессии и возвращает объект форме.
5. `catch` записывает сообщение и снова выбрасывает ошибку, чтобы форма тоже попала в ветку ошибки. `finally` выключает `submitting` для текущей сессии.

`async` позволяет использовать `await`. `await` ждёт результат Promise этой операции, а браузер продолжает работать. `try` содержит попытку, `catch` обрабатывает неудачу, `finally` выполняет завершающие действия и после успеха, и после ошибки.

`RESET` очищает данные и увеличивает `sessionVersion`. Поэтому ответ запроса, начатого до выхода или смены аккаунта, не запишет старые данные обратно в store и не изменит флаги нового запроса. Уже начатая операция на сервере при этом могла выполниться: сброс клиента её не отменяет.

## ApplyForm.vue по шагам

`props.job` — вакансия от родителя. В `data()` лежат локальные `form`, `errors` и `success`. Обычные `computed` читают из Vuex `submitting`, `submitError` и пользователя; `userId` безопасно получает ID, а `hasFieldErrors` циклом проверяет сообщения ошибок.

`created()` запускает `resetForm` при создании формы. Метод собирает имя из `firstName` и `lastName`, подставляет email и очищает письмо и сообщения. Watchers на `'job.id'` и `'user.id'` повторяют сброс при изменении вакансии или пользователя.

1. `v-model.trim` связывает имя, email и письмо с `form` и убирает пробелы по краям. Это изменение локальных данных, а не автоматическая запись на сервер.
2. `@submit.prevent="submit"` вызывает наш метод без перезагрузки. `novalidate` выключает стандартные всплывающие сообщения браузера; `validate()` показывает наши сообщения под полями.
3. Проверки: имя **2–100** символов; email базового формата и до **254**; письмо **20–5000**. Регулярное выражение проверяет вид email, а не существование почтового ящика. Action повторяет проверку перед запросом.
4. `fieldId` связывает label, поле, подсказку и ошибку по ID. `aria-invalid` и `aria-describedby` помогают объяснить ошибку средствами доступности. Атрибуты `required`, `minlength`, `maxlength` описывают ограничения полей.
5. `submit()` сначала выходит через `return`, если запрос уже идёт, успех уже показан или проверка не пройдена. Затем запоминает ID вакансии/пользователя и ждёт `dispatch('applications/submitApplication', ...)`.
6. Только после завершённого action для прежних ID выставляет `success = true`. В `catch` сообщение уже доступно из Vuex; введённые значения сохраняются для повторной попытки. Флаг ожидания завершает action, поэтому отдельный `finally` в форме не нужен.
7. Во время запроса `fieldset` блокирует поля; кнопка показывает ожидание и не принимает повторный клик. После успеха она тоже заблокирована. Редактирование вызывает `clearFeedback`, убирает старое сообщение и разрешает новую отправку.

Это защита от случайного повторного нажатия, а не запрет повторных откликов в базе. Стили формы и страницы управляют оформлением; `style scoped` ограничивает их компонентом, медиазапрос адаптирует расположение полей к узкому экрану.

## ApplicationsPage.vue по шагам

В `computed` читаются `loading`, `error`, getter `userApplications` и ID пользователя. `mounted()` запускает `loadApplications()` после появления страницы, а watcher `userId` повторяет загрузку при смене аккаунта. Метод передаёт работу action через `dispatch`.

Цепочка `v-if / v-else-if / v-else` выбирает состояние: загрузка → ошибка с повтором → пустой список → карточки. Пустой массив во время запроса ещё не означает отсутствие откликов. Кнопка «Попробовать ещё раз» вызывает тот же GET.

Карточки создаются `v-for` с `:key="application.id"`. Показываются вакансия, компания, статус, дата, имя, email и письмо. RouterLink с именем `job-detail` и `params.id` открывает связанную вакансию.

`companyInitial` берёт первую букву компании; `formatDate` проверяет и форматирует дату по-русски; `statusLabel` переводит известные статусы. Форма создаёт `submitted`, а изменение статуса работодателем не реализовано. Письмо выводится текстом через `{{ }}`, а CSS сохраняет его переносы строк.

## Какие объекты и запросы используются

Вакансия имеет поля `id`, `title`, `company`, `location`, `type`, `salary`, `description`. ID допускает строку или число; для избранного он обязателен. Форма передаёт action `{ job, name, email, letter }`, а тот создаёт POST-тело:

```js
{
  userId: 1,
  jobId: '12',
  jobTitle: 'Frontend developer',
  company: 'Example Company',
  name: 'Алия',
  email: 'aliya@example.com',
  letter: 'Хочу откликнуться на вашу вакансию.',
  status: 'submitted',
  createdAt: '2026-10-20T10:00:00.000Z'
}
```

Это пример, а не реальные отправленные данные. `userId` берётся из авторизации, время — из `new Date().toISOString()`. Сервер добавляет `id`. `jobTitle` и `company` сохраняют название вакансии на момент отправки.

В [axios.js](../src/api/axios.js) настроены клиенты с таймаутом 15 секунд. Вакансии используют `GET /Jobs` и `GET /Jobs/:id`, отклики — `GET /applications?userId=...` и `POST /applications`. Регистры имён ресурсов важны. Адреса задаются через [.env.example](../.env.example); отдельный адрес откликов необязателен. После изменения `.env` нужно перезапустить Vite.

## Как это подключено к команде

В [store/index.js](../src/store/index.js) оба модуля зарегистрированы рядом с `auth` и `jobs`. [JobCard](../src/components/JobCard.vue) получает `job`, вычисляет состояние сердечка getter-ом и вызывает action после `toggle`.

[JobDetailPage](../src/views/JobDetailPage.vue) загружает вакансию watcher-ом на ID маршрута с `immediate: true`: сразу и при смене URL. Проверяет, что объект относится к текущему ID, и подключает сердечко и форму. `:key="job.id"` создаёт новую форму при смене вакансии.

[auth](../src/store/modules/auth.js) вызывает `applications/reset` при новом успешном входе и выходе. `{ root: true }` позволяет вызвать action другого модуля. [Router](../src/router/index.js) направляет неавторизованного пользователя со страниц избранного/откликов на вход.

## Речь на 1–2 минуты

«Моя часть — избранные вакансии и отклики. Я сделал два Vuex-модуля, две страницы, форму и переиспользуемое сердечко.

Сердечко получает состояние через prop и передаёт родителю событие toggle. Родитель запускает action Vuex. Action добавляет или удаляет вакансию, меняет состояние через mutation и сохраняет JSON в localStorage. Поэтому карточки согласованы между страницами, а после перезагрузки избранное восстанавливается.

В форме имя, email и письмо связаны с данными через v-model. До отправки проверяются значения. Async action отправляет axios POST, а во время запроса кнопка заблокирована. Успех показывается после ответа сервера с ID. При ошибке сообщение отображается, а поля остаются заполненными.

Страница моих откликов делает GET, отбирает записи пользователя и показывает новые первыми. Есть загрузка, ошибка с повтором и пустое состояние. При выходе данные очищаются; поздний ответ старого запроса не возвращает их в store.

Здесь используются Vuex, props и custom events, директивы, computed, watchers, lifecycle и async/await. MockAPI — учебный сервис; для настоящего продукта сервер должен дополнительно проверять права доступа».

## Демонстрация на 5 минут

## Ответы преподавателю

1. **Зачем Vuex?** Общие данные нужны нескольким страницам и компонентам; отдельные копии могли бы разойтись.
2. **Action и mutation — одно и то же?** Нет: action организует работу и может ждать запрос; mutation синхронно меняет state.
3. **Зачем namespace?** Чтобы команды модулей не конфликтовали: `favorites/toggleFavorite` однозначна.
4. **Почему кнопка не меняет prop?** Источник состояния — родитель/store; ребёнок сообщает о действии событием.
5. **Что даёт F5?** Избранное восстанавливается из localStorage, отклики загружаются GET с сервера.
6. **Почему JSON?** localStorage хранит строки: stringify записывает массив как строку, parse восстанавливает.
7. **Computed или watch?** Computed возвращает значение, watch выполняет действие при изменении.
8. **Зачем key?** Vue различает записи списка; key вакансии на форме также создаёт новый экземпляр при смене ID.
9. **Почему два флага ожидания?** `loading` — GET списка, `submitting` — POST формы.
10. **Зачем finally?** Чтобы завершить ожидание после успеха и ошибки для актуальной сессии.
11. **Почему валидация дважды?** Форма показывает удобные ошибки; action проверяет данные даже при вызове из другого места.
12. **Что означает успех?** Сервер принял POST и вернул ID; это не подтверждение просмотра работодателем.
13. **Что если выйти во время запроса?** Номер сессии меняется, старый ответ не меняет новое состояние. Серверный запрос при этом мог выполниться.
14. **Чьи избранные видны после смены аккаунта?** Это общий список данного браузера, без привязки к пользователю.
15. **Фильтр userId защищает данные?** Он управляет отображением. Права доступа должен проверять сервер по подлинному токену.

## Проверки и ограничения

После упрощения проходят **28 из 28** проверок `npm test`, включая 5 проверок логики формы, и `npm run build`. [Тесты](../tests/features.test.mjs) используют подменённый API; отдельно ранее выполнены настоящий POST с ответом `201`, последующий GET сохранённых полей и удаление своей временной записи.

Автоматическое управление браузером в этой сессии недоступно: проверка всех экранов и действий в браузере не отмечена как выполненная. Проверки логики и сборки её не заменяют.

MockAPI публичный. Query `userId`, клиентский фильтр и Router guard не обеспечивают серверную защиту. Не отправляйте реальные персональные данные. Избранное не синхронизируется между устройствами. Сохранённая вакансия может устареть, а связанная серверная вакансия — быть удалена.
